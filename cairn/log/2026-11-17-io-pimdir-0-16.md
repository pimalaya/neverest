# io-pimdir 0.16

neverest moves from io-pimdir 0.15.1 to 0.16.0, released the same day with the CLI family audit's io-pimdir lines (PIM-1 to PIM-17 but PIM-10, PIM-13, PIM-15 and the format parts of PIM-12 and PIM-14; io-pimdir cairn/log/2026-11-17-*). No neverest code changed: the breaking parts (search paging by cursor, `PimdirMutateError::MoveInPlace`) are surfaces neverest does not use.

## What reaches neverest

- PIM-1: a `VTIMEZONE` rule with a huge `INTERVAL` no longer aborts a pull through the calendar summary derivation.
- PIM-7 and PIM-9: a rekey knows every old minted copy and is linear, so a second rekey or a delivered copy no longer makes another source remove the message from its server. This unblocks NEV-4 (contacts keyed from their first 256 KiB), whose fix rekeys stored cards.
- PIM-6: a mail binding joined to a message another source holds no longer derives an `Update` every run, and a first pairing keeps both sides' flags.
- PIM-14: a queued `move` into the item's own collection parks as `move-in-place`.
- PIM-8: a listing at the base revision keeps the summary and sort key of a locally edited contact or event.
- PIM-2: `store backup` and `store restore` never leave part of a file.
- PIM-16 and PIM-17: the extractor revision moved, so every search index is extracted again once.

## Spec

None: sync.md names io-pimdir behaviour by the pimdir format, which did not move (draft-13).
